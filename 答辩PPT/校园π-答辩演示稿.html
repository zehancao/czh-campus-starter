项目背景

校园学习、生活和管理信息分散，学生需要在多个渠道之间切换。

信息入口分散

课程、公告、交易、社团等信息来源不统一，查找效率较低。

学生高频需求多

课表、空教室、失物招领、二手交易、聊天等需求覆盖日常校园生活。

管理侧缺少闭环

商品审核、公告维护、投诉处理、安全事件处理需要后台统一支撑。

项目目标与意义

构建集学生端使用、后端处理和后台管理于一体的校园服务平台。

提升学生体验

将校园服务集中到移动端入口，降低信息获取和事务处理成本。

提升管理效率

通过后台管理端统一处理公告、审核、投诉、安全事件等事务。

提升工程能力

通过全栈项目实践完成需求分析、接口设计、前后端联调和多人协作。

系统总体架构设计

系统采用前后端分离架构，学生端与管理端通过统一 API 访问后端服务。

鸿蒙学生端

Spring Boot 后端

JWT 登录鉴权

统一 Result 响应

Vue 管理端

Vue3 + TypeScript
Naive UI 后台页面
ECharts 数据展示
Axios 接口调用

技术栈说明

技术选型围绕移动端体验、后端稳定服务和后台管理效率展开。

学生端

  • HarmonyOS
  • ArkTS / ArkUI
  • HTTP 请求封装
  • WebSocket 与文件上传

后端

  • Java 17 / Spring Boot
  • MyBatis-Plus / MySQL
  • JWT / BCrypt
  • Apache POI / 邮件 / 上传

管理端

  • Vue3 / TypeScript / Vite
  • Vue Router / Pinia
  • Axios / Naive UI
  • ECharts 数据可视化
